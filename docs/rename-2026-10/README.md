# 商品名リネーム（2026年10月 全店改変）— 資料の作り直し

決裁済みの資料3点を、**あとから書き換えられるようにしたもの**。
元は2026年9月11日に作ったきりで、作り直す手段がどこにも残っていなかった。

| 作るもの | 中身 |
| --- | --- |
| `out/商品名リネーム（2026年10月 全店改変）.pdf` | 決裁用の4ページ（写真つきカード・変更不要の表・運用ルール・再販時の修正） |
| `out/商品名リネーム 変更する商品（2026年10月 全店改変）.pdf` | 上の1〜2ページ目だけ＝名前が変わる13品（`python3 build.py --changes`）。海外に配る用 |
| `out/Age.3 Product Renaming Oct 2026 (EN/TH/ZH).pdf` | 同じ2ページの英語版・タイ語版・中国語版＋レシピ1枚（`--lang=all`） |
| `out/商品名リネーム（2026年10月 全店改変）.xlsx` | 全55品の一覧（商品名マスタ＋凡例） |
| `out/HP更新用マスタ（2026年10月）.md` | 公式HPに渡す36品ぶんの指示書 |
| `out/商品名リネーム 修正のお知らせ（2026年9月15日）.pdf` | 変わったところだけを1枚にまとめた周知用（`python3 build_notice.py`） |

**3点とも `master.json` 1つから作る。** 商品名を1か所直せば、PDFもExcelもHP用も同時に直る。
元の3点と見た目・中身が一致することは確認済み（PDFは実測した座標で組み直してある）。

## 直して作り直す

```bash
cd docs/rename-2026-10
pip install -r requirements.txt     # 最初の1回だけ
python3 build.py                    # out/ に3点が出る
python3 build.py --changes          # 名前が変わる13品だけの2ページ（日本語）
python3 build.py --changes --lang=all   # 日本語・英語・タイ語・中国語の4つ
python3 build_notice.py             # 周知用の1枚（master.json の "notice"）
```

直すのは **`master.json` だけ**。`build.py` は見た目を持っているだけなので、
文言・商品・区分を変えるときに開く必要はない。

### Excel で直したいとき

Excel（`out/…xlsx` の `商品名マスタ` シート）を直してから、

```bash
python3 import_xlsx.py 'out/商品名リネーム（2026年10月 全店改変）.xlsx'
python3 build.py
```

Excel に無い項目（PDFの理由書き・写真・並び順・HP用のファイル名）は元の設定を引き継ぐ。
行を足した／消した場合は最後に一覧が出るので必ず目で確かめること。

## master.json の中身

| キー | 何か |
| --- | --- |
| `meta` | 表題・方針・帯の右の文字・フッター・出力するファイル名 |
| `sections` | 各ページのリード文。`{n}品・{i}/{t}` は商品数とページ数が自動で入る |
| `callouts` `rules` | 3ページ目の囲み（表記統一・ジャンル帯の変更）と運用ルール4原則 |
| `legend` | Excel の「凡例」シート |
| `hp` | HP用mdの前書き・チェックリスト |
| `notice` | 周知用1枚の中身（見出し・赤帯・「修正前→修正後」の2品・結びの1行） |
| `i18n` | 英語・タイ語・中国語の文言（表題・リード文・バッジ・ラベル・ファイル名） |
| `items` | 商品55件。**ここが本体** |

### items の項目

| 項目 | 意味 |
| --- | --- |
| `no` | 日本メニューの番号。空（null）＝日本メニュー未掲載（海外店のみ・過去限定） |
| `group` `genre` | 大分類（Sweets／Savory）とジャンル帯 |
| `en` `ja` `old_en` | 新しい英語名・日本語名・現行の英語名 |
| `kind` | **和名維持 ／ 英語名変更 ／ 変更不要 ／ 再販時に修正**。この4つでページの行き先が決まる |
| `desc_en` | 英語説明文。入っている商品だけ、カードに説明文の枠が出る |
| `note` | PDFに出る理由書き（カードの下の1行、または表の「補足」） |
| `remark` | Excel の「備考」。PDFには出ない |
| `footnote` | カードのいちばん下に小さく出す一言（黒蜜たっぷりきなこだけ） |
| `card_seq` | 写真つきカードの並び順。1〜13が1〜2ページ目、14〜16が4ページ目 |
| `image` | `images/` の中のファイル名。無ければ写真なし |
| `hp` | HP用mdに出す商品だけ。`web_filename`（Web用の名前）と `dropbox_filename` |
| `reprint_row` | 例外。ラミントンだけ3ページ目と4ページ目の両方に出るので、4ページ目用の表記をここに持つ |
| `note_en` `note_th` `note_zh` | 理由書きの訳。無い言語は空欄になる（`footnote_*` も同じ） |
| `overseas` | **海外版だけ中身が変わる商品**。`en` `ja`（名前）／`photo_before`（旧画像。入れると「旧 → 新」で並ぶ）／`photo_labels`／`photo_changed` と `photo_tag`（赤い印）／`notice`（赤い注意の枠・言語ごとの文章）。日本語版には出ない |

### ページの割り付け

- **1ページ目** … `和名維持`（3品・説明文つきの大きいカード）＋ `英語名変更` の先頭5品
- **2ページ目** … `英語名変更` の残り（`build.py` の `first_page = 5` で分けている）
- **3ページ目** … `変更不要` の表 ＋ 囲み2つ ＋ 運用ルール4原則
- **4ページ目** … `再販時に修正`。写真があるものはカード、`desc_en` があるものは「和名維持」の表、
  残りは「英語名」の表

商品を足すと自動でこの区分に入る。カードにしたいときは `card_seq` と `image` を付ける。
**ページ割りは高さを測って自動で決まる**（`PAGE_LIMIT` より下にはカードを置かない）。
カードが高くなる言語・商品があっても、入らないぶんは次のページへ送られる。
それでも増やしたら必ずPDFを開いて確かめること。

## 資料の最後に足すもの

`attach/` に置いたPDFを、生成した2ページのうしろに足せる（いまはあんバターのレシピ1枚）。
`master.json` の `overseas.recipe` で、どのPDFを足すか・どの動画のQRを重ねるかを決める。
QRは `qrcode` で毎回作り直す。位置は `build.py` の `attach_recipe()`。

## 写真

`images/` に商品ごとのPNG（背景なし・高さ400px）。元は決裁済みPDFに入っていたものを取り出して、
印刷に足りる大きさ（実寸24mmで約420dpi）に縮めてある。
差し替えるときは同じ名前で上書きするか、`master.json` の `image` を新しい名前にする。

## 見た目を変えたいとき

`build.py` の先頭に、色とページ内の位置（pt）がまとまっている。
元のPDFから実測した値なので、**触ると元の資料と見た目がずれる**。
色は `DARK`（#222222）・`GOLD`（#C9A227）・`RED`（#C8362B）・`NAVY`（#2F4858）・`BEIGE`（#F4F1EA）。
ツール本体（`src/app/globals.css`）の配色とは別物なので、片方を変えても連動しない。

## 多言語版（英語・タイ語・中国語）

- 訳は `master.json` の `i18n`。商品ごとの理由書きは `note_en` / `note_th` / `note_zh`。
  **商品名（英語）と英語説明文はどの言語でも英語のまま**（メニューに載る名前そのものなので）。
  日本語名は「／ 月見照り焼き」の形で残してある（日本チームとやりとりするときの手がかり）。
- **文字が長いとはみ出す。** リード文は自動で折り返すが、上の帯の方針文と商品の理由書きは
  折り返さない。訳を直したら必ずPDFを開いて確かめること。
- 英数字はどの言語でも IPA Pゴシックで書く（元の資料と同じ見た目にするため）。
- **海外版だけ中身が違う商品**は `overseas` を持つ。いまは北海道あんバター1件。
  海外は北海道産に限定できないため `Anko & Butter ／ あんバター`。
  **写真は「旧 → 新」を矢印で並べる**（`photo_before`）。旧＝橙の「いま使う」、
  新＝灰色の「承認後」の印を付ける。さらに**赤い注意の枠**（名前は変更・画像は当面そのまま／
  レシピは後ほど共有）と、**①〜④の手順の帯**（`notice.steps`）。
  新しい形は、レシピ共有→試作→動画提出→専務の承認 のあとでないと売れないため。
  日本語版・Excel・HP用mdは `Hokkaido Anko & Butter` のままで、海外版だけ差し替わる。
  旧画像が `images/` に無いときは灰色の枠に「？」が出るので、抜けにすぐ気づける。
- **海外版だけ、最後にレシピのページが付く**（`overseas.recipe`）。
  `attach/anko-butter_recipe.pdf` をそのまま足して、右下の空きに
  **作り方動画のQRコード**（`recipe.video`）を重ねている。QRはビルドのたびに作り直すので、
  URLを直せばQRも変わる。日本語版（2ページ）には付かない。

## 必要なもの

- Python 3 と `reportlab` `openpyxl` `Pillow` `fonttools`（`requirements.txt`）
- 日本語フォント（IPA Pゴシック）。元のPDFと同じものを使っている。
  Linux なら `apt-get install fonts-ipafont-gothic`。Mac ではヒラギノを探しに行くので、
  **フォントが違うと字送りが変わり、折り返しの位置がずれる**ことがある。
- タイ語は Loma（`fonts-tlwg-loma-otf`）、中国語は WenQuanYi Zen Hei（`fonts-wqy-zenhei`）。
  Loma は CFF で reportlab が読めないため、初回だけ TrueType に変換して `.fontcache/` に置く
  （このフォルダは git に入れない）。
